# 오류 복구 처리 설계 검토 (미결)

작성일: 2026-07-24

잡 실행 중 발생하는 오류를 **복구 가능(READY 복귀)** 과 **복구 불가능(FAULT)** 으로
어떻게 나누고 처리할지에 대한 검토 문서. 일부는 구현했고, 핵심 설계는 미결로 남긴다.

---

## 배경

`ADC CAPTURE FAIL` 같은 오류가 발생하면 ERS는 HOST에 `FAIL`을 보내고 상태를
`READY`로 되돌린다(복구 가능 처리, [ERS_Main.py](../ERS_Main.py) `safe_error_stop_async`).
그러면 HOST가 다시 `TESTELSTART`를 보내고, 원인이 그대로면 또 실패한다.

실제로 관측된 문제: ADC 미연결 상태에서 HOST가 계속 재요청 → 매 사이클마다
부스터를 켜고 30V를 인가하며 무한 반복. ERS 쪽은 매번 정상적으로 멈췄지만,
잡과 잡 **사이**에는 상태가 없어서 반복을 끊지 못했다.

---

## 오류 구분 기준 (합의된 원칙)

핵심 질문: **"재시도하면 나아질 수 있는가"**, 그리고 **"장비 자체는 정상인가"**.

| 상황 | 장비 정상? | 재시도로 복구? | 판정 |
|---|---|---|---|
| ADC/릴레이 장치 미연결·미응답 | 예 | 사용자 조치 후 가능 | 복구 가능 → READY + FAIL |
| ADC 캡처 타임아웃·데이터 불량 | 예 | 가능 | 복구 가능 → READY + FAIL |
| 전원 노이즈로 USB 포트 일시 소실 | 예 | 노이즈 가시면 가능 | 복구 가능 → READY + FAIL |
| 전원 error_status ≠ 0 (과전압/과전류/과열) | **아니오** | 무의미 | 복구 불가 → FAULT |
| Modbus 연결 두절 | **아니오** | 무의미 | 복구 불가 → FAULT |

원칙: 장비는 멀쩡한데 외부 조건(연결/노이즈)이면 READY, 장비 자체가 이상하면 FAULT.

---

## 이미 처리한 것 (2026-07-24)

- **초기화 시 장치 존재 확인**: ADC(`/dev/ttyACM0`)·릴레이(`/dev/ttyUSB0`) 노드가
  없으면 잡을 받기 전에 FAULT. 고전압 인가 전에 미연결을 차단.
  (초기화 시점은 고전압이 없어 포트가 안정적이므로 존재 확인으로 충분. 통신
  확인은 하지 않음)
- **불필요한 `wait_for_relay_port` 제거**: 릴레이는 `set()`이 사용 시점에 포트를
  직접 열고, ADC는 capture마다 열며 재시도하므로 별도 대기 불필요.

---

## 미결 — 핵심 설계

### 문제: 잡 실행 중 포트 소실 시 무한 반복을 어디서 끊는가

전원 노이즈로 USB(ADC/릴레이)가 흔들려 포트가 사라지는 상황은 **복구 가능**으로
보는 게 맞다(노이즈가 가시면 정상 동작). 하지만 노이즈가 지속되면 무한 반복된다.

**결론(방향 A): ERS가 스스로 끊는다.**
- 이유: ERS가 장비 상태의 주인이다. HOST가 잘못 짜였거나 다른 HOST가 붙어도
  ERS가 무방비여선 안 된다. 특히 고전압 안전상, "믿을 수 없는 장비에 30V를
  반복 인가하지 않는다"는 결정권은 장비(ERS) 쪽에 있어야 한다.

**메커니즘: 연속 실패 카운터 → FAULT 승격**
```
포트 소실 → FAIL + READY        (일시적으로 보고 재시도 허용)
HOST 재시도 → 또 소실 → FAIL     (누적)
...
연속 N회 실패 → FAULT            (더는 일시적이 아님 → 승격)
성공 시 카운터 0으로 리셋
```
즉 복구 가능/불가능을 **정적 분류가 아니라 재시도 결과로 동적으로** 결정한다.

### 결정해야 할 사항

1. **연속 실패 임계값 N** — 예: 3회. 노이즈 지속 시간과 부스터 반복 인가 허용
   범위를 함께 고려.
2. **카운터 위치** — 오늘 문제는 잡과 잡 **사이**의 반복이었다. 따라서 잡 1회
   내부(idx 루프)가 아니라 **잡 간(HOST 재요청 간)** 카운터가 필요하다.
   `cmdTestStart`/`worker` 진입 시점 기준으로 유지·리셋 위치를 정한다.
3. **FAULT 탈출 경로** — 현재 FAULT는 서비스 재시작 외에 빠져나올 방법이 없다
   (`cmdTestStart`가 `device_state != "READY"`면 잡을 거부, [ERS_Main.py](../ERS_Main.py)).
   장치 미연결/노이즈처럼 사용자가 조치하면 복구되는 FAULT의 경우, HOST가
   `RESET`/재초기화 명령으로 장치 재확인 후 READY로 돌아오는 경로를 만들지 검토.
   (안 만들면: ADC를 나중에 꽂아도 재시작 전까지 FAULT 유지)

### 추가로 볼 것

- **전원 error_status / Modbus 예외를 FAULT로 승격** — 현재 이들이 어느 경로로
  가는지([ERS_Main.py](../ERS_Main.py) `POWER ERROR FAIL`, `POWER MONITORING FAIL`
  등) 확인하고, 복구 불가 항목은 명시적으로 FAULT로 보낸다.
- **ADC 재시도 파라미터 조정** — `adc_capture_attempts`(현재 3),
  `adc_capture_retry_delay_sec`(현재 1.0초)를 노이즈가 가실 시간을 주도록 조정할지.
- **릴레이 통신 확인** — 초기화에서 존재만 확인 중. 필요 시 RELAY_PWREN 켜고
  `test_clear`가 정상인지까지 확인하는 방안(초기화 절차 복잡해짐).
- **ADC 통신 확인** — 존재만이 아니라 실제 통신으로 확인하는 방법이 있다고 함
  (구체 방법 추후 정리).
